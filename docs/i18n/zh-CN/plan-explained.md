# 不带术语的计划

**问题。** 主机游戏是为主机的处理器、图形芯片和系统编写的程序。
Xbox Series 的处理器与 PC 上的是同一类，所以程序的大部分原样就能在 PC 上运行。
有两件事挡住了去路：负责绘制画面的小程序（着色器）是为主机的 AMD 图形芯片写的，
而游戏调用的系统函数（内存、文件、声音、手柄）在 Windows 上并不存在。
每个兼容性项目都得翻译这两样东西，而且每一个都在单打独斗。

**我们换一种做法。** 我们把主机的真实行为作为测试写下来：“这条指令，输入这些值，得到这些输出”。
多个人在真实硬件上运行这些测试，只有他们结果一致，结果才算数。然后任何项目都可以拿这些测试去对照自己的翻译器，
逐行看到它哪里出错。

**各个阶段**

0. **基础建设** — 规则、检查每一份贡献的机器人、文档。完成标准是：新人，无论是人还是 AI，
   无需任何人帮助就能领取任务并让它被接受。
1. **共享知识** — 测试本身，按领域划分：图形指令、内存、声音、存储、
   手柄。完成标准是：每个测试都有由两位独立的人确认的结果。
2. **适配器** — 小型连接器，让其他项目的翻译器对照我们的测试运行，并有一张公开的表，
   显示谁通过了什么。
3. **上游修复** — 当表中显示另一个项目有漏洞时，我们向该项目提供修复。
4. **共享组件** — 多个项目需要而目前没有任何项目拥有的部件，在这里作为库来构建。

从阶段 1 开始，一切都并行进行：每个任务只等待它所依赖的任务。

**我们绝不做的事：** 分享任何游戏中的东西（文件、代码、图片、声音）、破解保护，或链接到泄露资源。
我们测试的一切都是为此专门手写的。

**如何关注进展：** [进度页](https://github.com/scarlett-commons/scarlett-commons/blob/status/PROGRESS.md)会在看板有变化时自动更新。每个任务都是 GitHub 上的一个 issue；
任何人都可以领取。
