# Как участвовать

ИИ-агенты приветствуются на тех же условиях, что и люди. Тот, кто запускает агента, отвечает за то, что агент
публикует.

## Pull request

- Одна задача на один pull request, с `Closes #<номер задачи>` в описании. Задача должна быть закреплена за
  вами (сначала напишите в ней комментарий `/claim`).
- Каждое изменение кода (`bot/`, `tools/` и `src/`, когда появится) сопровождается тестом в `tests/`, который
  падает без этого изменения. Документация (`docs/`, `*.md`) и случаи (`cases/*.json`) кодом не считаются:
  PR с документацией не требует теста (напишите `Tests: n/a (docs)`), а случай проверяет `tools/cases.py`,
  который CI запускает в каждом PR.
- Изменения движка (`engine/tools/`, `engine/runtime/src/`, `engine/runtime/shims/`) требуют теста в
  `engine/tests/` или `engine/runtime/test/`, а задействованные задачи CI движка должны быть зелёными, либо
  нужна пометка об известной красной ([docs/engine-dev.md](./engine-dev.md)). Падение на базе там проверяют
  рецензенты, а не `verify`.
- Заявки: не больше двух одновременно (шесть для мейнтейнеров); заявка без pull request истекает через 72 часа.
- Не больше 1500 изменённых строк, если мейнтейнер не добавит метку `large`.
- Каждый коммит содержит строку `Signed-off-by:` ([DCO](https://developercertificate.org/)): вы подтверждаете,
  что вправе передать его под лицензией этого проекта.
- Раздел `Provenance:` в описании перечисляет, откуда взят код, по одной строке на источник:

      Provenance:
      - original
      - https://github.com/owner/repo (GPL-3.0-or-later): src/foo.rs, adapted

  Допустимые лицензии: GPL-3.0, GPL-3.0-or-later, LGPL-3.0, MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, Zlib,
  ISC. Код, прочитанный в проекте под любой другой лицензией (GPL-2.0-only, вообще без лицензии), тоже нельзя
  переписать в этот проект: это всё равно производное произведение. Вместо этого запишите факты (формат,
  поведение) в `docs/`, указав, откуда вы их узнали.

## Если бот закрыл ваш pull request

В комментарии при закрытии перечислены все причины. Исправьте их и откройте pull request снова (или откройте
новый): бот проверит его ещё раз. Если считаете правило неверным, откройте issue типа Bug с цитатой этого
комментария; правила меняются только рецензируемым pull request в `bot/rules.py`.

## Что бот закрывает сразу (жёсткие правила)

- Любой файл, похожий на данные игры: запрещённое расширение, известная сигнатура медиа или исполняемого файла
  или двоичный файл вне `docs/images/`.
- Нет `Closes #<задача>` или задача не закреплена за автором.
- Другой открытый pull request уже закрывает ту же задачу (поздний закрывается).
- Строка `Provenance:` с недопустимой лицензией или нет раздела `Provenance:`.

## Что бот даёт короткое время исправить (мягкие правила)

- Падающий CI, нет теста, тест, который проходит и без изменения, нет подписи, слишком большой размер.
- Срок зависит от загруженности проекта: 48 часов при менее чем 5 активных людях, 24 при 5 и более, 8 при 20
  и более, 4 при 50 и более. На полпути, если автор молчит, бот открывает задачу `Finish #N`, чтобы кто-то
  другой мог доделать работу.

## Тесты должны что-то доказывать

`verify` запускает тесты, которые добавил или изменил pull request, на **старом** коде. Если изменился код
(`src/`, `bot/`, `tools/`), хотя бы один из них должен там упасть. Тест, проходящий без изменения, его не
проверяет.

## Рецензии

Рецензировать может любой, люди и агенты, но засчитываются только рецензенты, выбранные ботом случайно для
текущего коммита, и только в форме из AGENTS.md. Доверенные рецензенты (три слитых pull request и более) весят
1, новые 0,5; для слияния нужен балл 2 минимум от двух из них, отсутствие действительного reject, совпадающие
воспроизведённые логи тестов, зелёный CI и 24 часа без push. Мейнтейнер может остановить слияние командой
`hold`.

## Результаты на железе

См. [docs/results.md](../../results.md): результат засчитывается, когда двое разных людей сообщают один и тот же
хеш вывода для одного и того же теста, коммита и класса железа.
