# Дорожная карта

Это план, по которому работают все. Каждый пункт превращается в задачи (issues) с меткой своего направления; бот
выдаёт их в порядке зависимостей. Ход работ отслеживается автоматически на [странице хода работ](https://github.com/scarlett-commons/scarlett-commons/blob/status/PROGRESS.md).

**Цель:** сделать сложные общие части запуска программ Xbox Series X|S на ПК правильными и проверенными один раз,
для всех проектов по совместимости, а не пятнадцать раз. Мы создаём знания, тесты и проверенные компоненты;
другие проекты ими пользуются.

**Никогда:** данные игр, ключи, расшифровка, ссылки на утечки, код под несовместимыми лицензиями (см. CONTRIBUTING.md).

## Приоритет

Сначала стабильная, играбельная сборка, как можно быстрее: задачи с меткой `priority:playable` (docs/engine-plan.md, раздел «Priority»). Всё остальное либо поддерживает её, либо идёт после неё.

## Трек движка (параллельно каждому этапу)

Рекомпилятор в `engine/`, импортированный из продолжения Leonida вместе с историей и поддерживаемый в
соответствии с ним ежедневной синхронизацией (docs/engine-sync.md). Работа над ним подчиняется тем же правилам,
что и всё остальное, а его успехи на реальных играх отмечаются по хешу сборки (docs/title-runs.md): загружается,
импорты разрешены, устройство создано, первый кадр, меню, в игровом мире, играбельно. Этапы ниже делают его
правильным; трек движка делает так, чтобы он работал. Его задачи с готовыми инструментами для каждой: [docs/engine-plan.md](../../engine-plan.md).

## Этап 0: Фундамент (готов)

Механизм, позволяющий людям и агентам присоединяться без чьей-либо помощи.

- Бот: проверка правил, заявки, сроки, задачи на доработку, `/split`, слепые рецензенты, автослияние, режим
  пробного прогона.
- Документация: эта дорожная карта, архитектура, быстрый старт, AGENTS.md, переводы.
- Страница хода работ, генерируемая из доски задач.
- Зеркало на втором хостинге; процедура восстановления.
- Автоматические предложения мейнтейнерам.

**Готово, когда:** новый агент может прочитать AGENTS.md, взять задачу и добиться слияния pull request, при том
что участвуют только его рецензенты, а других людей нет.

## Этап 1: Общие знания

Библиотека тестов, определяющая правильное поведение, проверенная на реальном железе.

| Направление | Что | Метка |
|---|---|---|
| Шейдеры | Независимые от формата случаи RDNA2: VALU f16/f32/f64 (округление, денормализованные числа, FMA), SALU, LDS, wave64 и межпотоковые операции, изображения и сэмплеры, адресация буферов, интерполяция и экспорт | `area:shaders` |
| Эталон на железе | Ожидаемые результаты, подтверждённые на реальных AMD RDNA2 и распространённых видеокартах для ПК, по консенсусу (docs/results.md) | `area:results` |
| Системные API | Спецификации поведения по открытой документации и тестам на homebrew или примерах Microsoft: память, потоки, файлы, время | `area:system` |
| Графический API | Расширения D3D12 консоли и настольные D3D12/Vulkan: что отличается и как каждый проект это сопоставляет | `area:graphics` |
| Звук, хранилище, ввод | Спецификации поведения и тесты для XAudio2, DirectStorage, GameInput | `area:audio`, `area:storage`, `area:input` |

**Готово, когда:** у каждого случая есть ожидаемый результат, подтверждённый двумя независимыми отчётами.

## Этап 2: Адаптеры и таблица совместимости

- Запускатель для каждого транслятора: SPIR-V на Vulkan, DXIL на D3D12, HLSL. Транслятор каждого проекта
  подключается командой.
- Публичная таблица: какой проект проходит какие случаи, пересоздаётся при каждом запуске.
- Запуски на Linux и macOS (Vulkan, MoltenVK). Метка `area:platforms`.

**Готово, когда:** в таблице работают как минимум три внешних транслятора.

## Этап 3: Исправления в чужих проектах

Каждая ошибка, которую таблица показывает в другом проекте, становится небольшим протестированным исправлением,
предлагаемым этому проекту. Обращение к проектам идёт сначала через issue `outreach`; мейнтейнер решает, что
отправить, один раз и в собственном трекере этого проекта.

## Этап 4: Общие компоненты

Там, где одна и та же деталь нужна нескольким проектам и ни у кого нет хорошей под совместимой лицензией,
создаём её здесь как библиотеку со своими тестами (например, эталонный интерпретатор RDNA2, который служит
эталоном, когда железа нет под рукой).

## Направления параллельно

Все этапы после 0 идут одновременно; задачи ждут только своих зависимостей. Метки: `area:shaders`,
`area:results`, `area:system`, `area:graphics`, `area:audio`, `area:storage`, `area:input`, `area:platforms`,
`area:infra`, `area:docs`, `area:i18n`; трек движка добавляет `area:cpu`, `area:hooking`, `area:recomp`,
`area:difftest`, `area:diagnostics`, `area:memory`, `area:gpu` (docs/engine-plan.md).
